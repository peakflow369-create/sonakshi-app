# SONAKSHI: offline-first personal voice assistant (Android)

```
 mic ──> Porcupine (foreground svc, ~idle) ──"Turn on Sonakshi"──> broadcast com.sonakshi.WAKE
                                                                         │
                                  MacroDroid: chime + data ON + wake screen + launch app
                                                                         │
 Capacitor app (offline Three.js UI) ── on-device STT ──> POST /ask ──> FastAPI ──> Gemini
        │                                  (data is up)                  └─> {"reply": "..."}
        └── local TTS speaks reply ── 8 s of silence ──> broadcast com.sonakshi.SLEEP
                                                                         │
                       MacroDroid: data OFF.  App: moveTaskToBack, Porcupine resumes
```

Design choice vs. your spec: the app POSTs to the backend itself (the WebView already has the text),
so MacroDroid only does what only it can: **network on/off, chime, launching**. Fewer hops, less latency.

## 0. Realistic limits (read first)
1. **Mobile data toggling on a non-rooted phone.** `pm grant` cannot give anyone `MODIFY_PHONE_STATE`
   (signature permission). Non-root options: MacroDroid's *Shell script* action running `svc data enable|disable`
   via its ADB-hack/Wireless-debugging mode, or Shizuku. `WRITE_SECURE_SETTINGS` alone covers settings-level
   toggles, not radios. Test `svc data disable` from `adb shell` first; if that works, the macro will too.
2. **"Zero passive battery"** is not literally possible: an always-listening mic needs a foreground service
   (permanent low-priority notification, and the mic-in-use indicator on Android 12+). Porcupine is
   cheap (~1% CPU class), but it is not zero. Everything *else* here is zero while idle: no render loop,
   no TTS/STT objects, no network.
3. **Android 14+**: a microphone foreground service may only be started while the app is visible.
   So open the app once after every reboot (it starts the ears). A boot-start is not allowed.
4. **Picovoice AccessKey** is validated by their SDK; check on your plan whether init needs internet.
   The service builds Porcupine once at start (when the app was opened with data on) and only
   toggles `start()/stop()`, so later wakes happen fully offline.
5. **Offline STT** needs the offline English pack: Settings → Google → Speech → Offline speech recognition.
   Otherwise the first utterance races the data coming up.
6. **Hosting**: Render's free tier sleeps and cold-starts in 30–60 s, which breaks an 8 s session.
   Prefer Vercel/Cloudflare, or Render + an external pinger. Gemini free tier adds rate limits.

## 3. Wake word "Turn on Sonakshi"
1. Picovoice Console → Porcupine → *Train custom wake word*, phrase `Turn on Sonakshi`, language English,
   platform **Android**. Download `sonakshi_android.ppn` → `android/app/src/main/assets/`.
   (Check your plan's limits: the free tier restricts commercial use and model validity.)
2. Put your AccessKey in `android/gradle.properties` as `PICOVOICE_KEY=...`.
3. Tune `setSensitivity` in `WakeWordService.java`: raise if it misses you, lower if it false-triggers.
4. Keep the `.ppn` and keys out of GitHub (already in `.gitignore`).

## 4. ADB setup (phone connected via USB debugging; permissions persist)
```bash
# MacroDroid
adb shell pm grant com.arlosoft.macrodroid android.permission.WRITE_SECURE_SETTINGS
adb shell appops set com.arlosoft.macrodroid SYSTEM_ALERT_WINDOW allow     # launch UI from background/lockscreen
adb shell dumpsys deviceidle whitelist +com.arlosoft.macrodroid
# Sonakshi
adb shell pm grant com.sonakshi.app android.permission.RECORD_AUDIO
adb shell pm grant com.sonakshi.app android.permission.POST_NOTIFICATIONS
adb shell dumpsys deviceidle whitelist +com.sonakshi.app
# sanity check for the radio toggle
adb shell svc data disable && adb shell svc data enable
```
Also set both apps to **Battery: Unrestricted** and lock them in Recents.

## 5. MacroDroid macros
**Macro 1: Sonakshi Wake**
- Trigger: *Intent Received* → action `com.sonakshi.WAKE`
- Constraints: none (optionally: *not in a call*)
- Actions, in order:
  1. *Speak Text* → "Systems active" (device TTS, don't wait)
  2. *Shell Script* → `svc data enable` (add `svc wifi enable` if you use Wi-Fi), run as ADB/shell
  3. *Screen On* (optionally *Disable Keyguard* if you want it fully hands-free)
  4. *Launch Application* → Sonakshi
- Optional failsafe action: *Wait 90 s* → *Shell Script* `svc data disable`

**Macro 2: Sonakshi Sleep**
- Trigger: *Intent Received* → action `com.sonakshi.SLEEP`
- Actions: *Wait 1 s* (lets the last HTTP finish) → *Shell Script* `svc data disable` (+ `svc wifi disable`)

**Macro 3 (optional): Push text into the UI**
- Any trigger → *Send Intent* → action `com.sonakshi.TEXT`, target *Broadcast*,
  extras: `text` = `{whatever}`, `speak` (boolean), `prompt` (boolean: treat as a user question).
  The plugin forwards it to JS as the `macrodroidText` event.

## 6. Backend
```bash
cd backend && pip install -r requirements.txt
export SONAKSHI_KEY=... NOTIFY_KEY=... GEMINI_API_KEY=...
uvicorn main:app --host 0.0.0.0 --port 8000
curl -X POST localhost:8000/ask -H "X-Sonakshi-Key: $SONAKSHI_KEY" \
     -H "Content-Type: application/json" -d '{"text":"what is the capital of Kerala"}'
```
Stateless apart from a 3-exchange memory that resets after 2 min idle. Audio is transcribed on-device,
so the payload is a few hundred bytes of text.

## 7. Lifecycle (what actually runs when)
| Phase | Running | Not running |
|---|---|---|
| Idle | Porcupine only | UI render, STT, TTS, network |
| Wake → reply | STT, TTS, WebView, network | Porcupine (mic released) |
| 8 s silence | → SLEEP broadcast, data off, task backgrounded, Porcupine restarts | everything else |

## 8. Updates feed, notifications and `/api/notify`

```
n8n (6:30 AM IST) ── POST /api/notify (NOTIFY_KEY) ──> FastAPI ──┬─ feed.json (last 200)
                                                                 ├─ SSE /api/stream ──> open app/tab: drawer + notification
                                                                 └─ Web Push ──────────> closed browser/PWA: notification
```
**Two keys.** `SONAKSHI_KEY` ships inside the app/web build (ask + read the feed). `NOTIFY_KEY` stays in n8n and is the
only key that can *write* to the feed. If `NOTIFY_KEY` is unset it falls back to `SONAKSHI_KEY`: set it.

**n8n node** (HTTP Request): `POST https://YOUR-BACKEND/api/notify`, header `X-Sonakshi-Key: <NOTIFY_KEY>`,
body *Using Fields Below* (no JSON escaping needed for long news text):

| field | value |
|---|---|
| title | `Morning Briefing - Sonakshi` |
| text | `{{ $json.text }}` |
| timestamp | `{{ $now.toISO() }}` (keeps the +05:30 offset; a hard-coded `...Z` is read as UTC and shows 5½ h late; leave it out and the server stamps "now") |
| category | `morning_briefing`, `bible_verse`, `news` or `notification` (aliases like `verse`, `system` also work) |

```bash
curl -X POST "$BACKEND/api/notify" -H "X-Sonakshi-Key: $NOTIFY_KEY" -H "Content-Type: application/json" \
  -d '{"title":"Daily verse","text":"Test message","category":"bible_verse"}'
# -> {"ok":true,"id":"...","seq":1,"live_listeners":0,"push_devices":0}
curl "$BACKEND/api/feed?after=0" -H "X-Sonakshi-Key: $SONAKSHI_KEY"
```

**Where notifications work**
| Where | How | When the app/tab is closed |
|---|---|---|
| Android app (Capacitor) | `@capacitor/local-notifications` when the stream delivers an item | no: the app sleeps with data off by design. It catches up when opened (unread badge). Keep MacroDroid TTS for the 6:30 voice briefing |
| Chrome/Edge/Firefox, Android Chrome | service worker + Web Push (VAPID) | yes, once `gen_vapid.py` keys are on the backend |
| iPhone | Web Push works only for the site added to the Home Screen (iOS 16.4+) | yes, as installed PWA |

**Web build** (optional): `cd app && npm run build:web`, then the backend serves `app/www` itself (same origin, needs HTTPS in production
for the service worker). Anything in `config.js` is readable by whoever can load the page, so put the site behind your own auth
if the feed content is private.

**Web Push setup:** `cd backend && python gen_vapid.py`, set `VAPID_SUBJECT`, restart. Free hosts with ephemeral disks lose
`feed.json` / `push_subs.json` on restart; set `DATA_DIR` to a persistent volume if that matters.

**After pulling this update:** `cd app && npm install` (new dep `@capacitor/local-notifications`), `npm run build`,
and add `NOTIFY_KEY` / `ALLOWED_ORIGINS` to the backend env. Your existing `config.js` keeps working.
